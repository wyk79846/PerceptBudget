# v4平稳执行期的视觉反馈实验

目的：原v4按预测动作安排刷新，Continue期间不采新图，无法发现执行中刚出现的问题。本实验补充少量真实腕部图像，先尝试捕捉可见滑落，保持原v4可独立运行。

## 做法

1. 只在无推理进行、原计划仍允许Continue、且正在执行闭爪命令时，每5个控制步采一次腕部图像。采图不推进仿真，也不把监测图冒充下一次VLA的双图输入。
2. 在夹爪指尖外侧的小区域跟踪纹理。手臂确实移动、背景也移动，而该区域的纹理保持稳定，才建立“可能随手携带”的参考。不是用整图画面差分直接报警。
3. 参考纹理大面积丢失连续出现两次时报警；如果同时出现未开爪却夹口缩小过半，则允许图像与夹口的联合证据直接报警。正常开爪重置参考，同一次闭爪不重复报警。
4. `observe`只记录；`refresh`默认在确认报警后暂停执行，恢复频率时也不消费旧动作，采最新双图进行Full预测，结果就绪后从新动作第一步恢复。这次预测不使用已出错的旧动作作RTC约束；普通刷新仍保持原RTC。没有增加夹爪重试规则。

在线输入只有当前腕部RGB图、机械臂8维实际状态和正在执行的动作。物体位置、接触真值、最终成功/失败仅用于离线核对，不传给监测器。目前没有训练网络，也没有修改FlashRT。

## 已有结果

|范围|回合|平稳闭爪期采样|报警|有局部物理异常对应|
|---|---:|---:|---:|---:|
|旧开发轨迹|12|148|1|1|
|未参与规则设计的task7–9轨迹|24|250|0|0|

12条开发轨迹含两次抬起后掉落：识别1次，另1次漏检。识别例在物理掉落记录后2个控制步报警，腕部画面可见物体相对手移动、夹口随之收缩。当前没有其他报警，但24条验证轨迹没有提供新的掉落阳性，不能据此证明普遍检出率。

固定设置：采样间隔5步；持续丢失确认2次；至少4处可跟踪纹理；模板匹配相关性0.65；丢失比例0.75。其余几何门槛见实现。第一版设置统一，不按任务或种子改阈值。

## 第一版异步响应的闭环结果

4任务进行监测关闭/开启配对，共8回合、1次模型加载。两组均3/4成功，三项成功任务均保持，Object2两组都超时。

- 监测组真实采图33次；唯一报警有抬后滑落证据：63步发生，65步报警并提交Full，原v4下一次刷新为67步。没有其他报警；这次提前刷新仍未挽回任务。
- 单次采图平均3.86ms；检测中位1.18ms、平均3.59ms。采图加检测累计约0.246s，全部计入任务计时和板级能量。
- 四任务总能量546.47→548.27J，增加0.33%；两组均33次推理。这里只是小样本实际成本，不能外推为固定开销，也没有证明提高成功率。
- 8回合系统、频率及配对初始输入审核通过，零断供，频率已恢复。汇总阶段曾误读不存在的末尾等待字段，已修复，并从完整原始数据恢复报告，没有重跑或删改成败。

这一轮完成的是“部分可见异常的采图—判断—Full响应”实验路径。当前保持可选开关，不替换默认v4。后续若要处理从一开始就空夹，需要另外定义视觉证据与标签，不能沿用本轮滑落检出率。

## 报警后先停、再重新预测

用户指出第一版报警后仍执行旧动作不合适，因此新增`stop_and_replan`响应：报警当步起不再推进控制步，等待频率恢复与新Full完成；不沿用已出错的旧动作约束，实际消费延迟为0，新chunk不丢前缀。暂停产生的零步延迟不计入正常异步延迟队列。暂停时间和能量照常计入任务。

本仿真里的停执行沿用现有关键等待的语义：等待期间不调用`env.step`，并记录停止与恢复时刻。单测仍使用seed67/init1的Object2，监测阈值未改。第一版原始成败与数据保持不变。

单测已完成：报警前65个控制动作及对应机械臂状态与前一版完全相同；仍在第65步报警。停执行0.807秒后在同一控制步接上新chunk，期间执行旧动作0步，丢弃新动作0步。随后66步开爪、84步重新闭爪，151步成功；旧异步响应280步超时。任务时间9.67秒，总能量114.90J，原为182.68J。系统、停止区间及频率审核通过、零断供。

这是单任务有效结果，同时改变了停执行和取消失败尾段引导，不能把收益单独归因于暂停，也不能推断总体成功率。[单测报告与原始索引](/home/wyk/workspace/任务产出/perceptbudget/M4/20261111T113141Z-v4-visual-monitor/stop_replan/results.md)。

这是有限范围的局部反馈：从一开始就空夹、画面看不见物体、没有足够稳定参考的情况可能漏检。正常晃动、遮挡和不同腕部安装位置仍需进一步验证。当前规则不会把“闭爪”本身当成“已抓住”。

## 运行

在原v4评测命令后添加：

```bash
--visual-monitor observe
# 或开启报警后的Full响应：
--visual-monitor refresh
# 显式指定默认的停等响应：
--visual-monitor refresh --visual-response stop_and_replan
# 如需复现第一版报警后继续执行旧动作的实验：
--visual-monitor refresh --visual-response async
# 同一常驻模型进行开关配对：
--visual-monitor refresh --visual-monitor-pair
```

默认不启用。`action_signals_v4.json`不变；冻结标签`v4-final-20261111`保留。

采图耗时和检测耗时分别记录，均在任务计时和板级总能量窗口内；监测图与VLA请求图分别保存。不能仅用CPU检测约1–3ms代表全部监测开销。
