# 项目进度

更新日期：2026-11-12。

## 目的

为灵玑 OS 构建更加省电、同时追求高准确率的 VLA 推理方案，使机器人能够在有限端侧资源下持续感知、推理和执行动作。当前以完整任务的成功率、板级能量、完成时间和动作供给情况评价方案。

## 已完成

### 推理与执行

- 已接通 π0.5、FlashRT 感知上下文和 OpenPI 动作专家，固定 H=50、N=5、BF16。
- 已实现真实异步控制与完整 VJP RTC，通过 source-step CUDA Graph、条件缓存、FlashAttention 和融合归一化执行动作求解。
- 已实现基于剩余动作的感知刷新，包含夹爪切换、减速、转向和同位置新旧动作变化。
- 已接入 Full/Fast/Continue 运行模式及高、中、低三档频率。关键刷新使用高频，普通刷新优先选择满足时限的中频，Continue 使用低频。
- 已接入板级功率采样、动作来源与交接记录、频率恢复、GPU 锁和资源异常续测；完成回合的成功及失败均保留。

当前运行策略已完成闭环验证；在统一窗口内联合比较所有计算、变频与保持能量并选择最小能量候选，仍属于待完善范围。

### AGX Orin 64GB

2026-11-11 已完成运行环境准备、权重校验、FlashRT 与 CUDA 运算检查、LIBERO EGL 取图，以及原生模型和 RTC 功能验证。

固定输入延迟验证：

| 路径 | 耗时 | 验证范围 |
|---|---:|---|
| FlashRT 原生 π0.5，不带 RTC | 160.722、160.587 ms | 预热后两次功能验证计时 |
| RTC eager VJP | 中位数 917.21 ms | 12 次，参考路径 |
| Full＋RTC source-step CUDA Graph | 中位数 299.58 ms | 12 次，298.99–300.39 ms |

共同配置为 H=50、N=5、BF16、state 开启、RTC beta=5、GPU 1,300.5 MHz。RTC 测试使用 executed=5、delay=2、45 步旧动作尾段、665 个有效前缀 token。正式图路径启用确定性运行设置与条件缓存；同输入参考校验的动作最大绝对误差、VJP 范数最大绝对误差均为 0。

RTC 计时包含视觉上下文、动作求解、CPU 动作输出及解码；不含取图、外部图像/state 预处理、控制执行、模型加载和图准备。原生模型计时为同步后的 `model.predict` 调用，外部动作解码不计入。两条路径使用不同动作求解后端，差值不能全部解释为 RTC 引导自身的成本。

AGX 当前验证的是运行可行性与固定输入延迟。Full/Fast/Continue 的完整设备标定、真实异步闭环成功率及整任务能量尚待测量。

### 抓取反馈与视觉监测

已完成旧 200 回合的夹爪事件与执行来源核对，以及其中全部 50 个 Object 回合的接触分析。Object 的 9 个失败回合中，7 个未稳定拿起目标，2 个曾抬起后在闭爪状态下掉落。这些记录用于定位抓取问题，后续参数与规则仍通过独立实验验证。

可选腕部视觉监测已验证采图、判断、报警停等和重新规划的运行路径；CPU 持物识别也已进入实验。当前分别核对报警正确性、误报、无法确认和漏检，任务最终成功率单独统计。少量恢复实例和单批成功数还不足以证明整体准确率提升。

视觉实验入口见[视觉异常监测](experiments/visual_monitor/README.md)。冻结 v4 可独立运行，视觉反馈通过显式参数启用。
