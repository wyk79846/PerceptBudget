# PerceptBudget M3阶段交付报告

日期：2026年10月28日

## 1. 阶段结论

M3已实现Full＋Continue的真实异步闭环：读取未来动作中的夹爪切换、减速和转向，计算刷新截止时间，在等待期间降频，并为下一次刷新恢复高频，最后通过RTC按实际动作执行进度交接。Fast动态选择留到M4。

四组比较中，动态刷新联合调度D组成功8/9、平均每回合122.62 J；相较同样动态刷新但恒定高频的B组，平均能量减少约7.3%，成功数相同。C、D差距较小，当前不能声称联合提前恢复显著提高成功率。所有已纳入比较的回合均无实际动作断供。

**本阶段选定额外余量η＝25 ms。四组主比较使用50 ms；25 ms依据后续两轮独立对照确定，不将50 ms四组结果写成25 ms的结果。**本报告先交付实验与结论，当前代码默认仍为50 ms，后续启用25 ms时需同步冻结配置。

## 2. 固定配置与计量口径

- 平台：本机Jetson；保持功耗模式不变，仅控制已有GPU、EMC频率组合，CPU频率保持一致。
- 模型：lerobot/pi05_libero_finetuned_quantiles_v044；checkpoint revision b6bfb493bc0f21c4ab24d816409ea3cebf5e43bd；H＝50、去噪N＝5、BF16模型、FP32 RTC求解、state启用、容量200、RTC引导上限5。
- 推理：FlashRT感知上下文＋OpenPI动作专家完整VJP RTC，保留已经验证的图执行、注意力、融合norm与autotune优化。RTC按真实执行进度对齐，不把推理期间动作当作未执行新缓冲。
- 高频：GPU1173 MHz、EMC3199 MHz、CPU1497.6 MHz；低频等待：GPU816 MHz、EMC2133 MHz、CPU1497.6 MHz。
- Full使用完整双视角及state；Continue只执行已有动作，不新增神经推理。正式触发使用原机制一，去噪触发与事件合并关闭。
- 主比较：Spatial/Object/Goal各task1、3、6，共9任务×4组；seed＝7、init＝0，组序轮换。
- 能量：整任务板级能量，含失败尝试及任务判定结束后已发推理的收尾。模型加载、编译与预热不计入任务能量。
- 完成时间：从任务计量开始到成功/失败判定的真实墙钟时间；另保存收尾结束时间。执行步数单独报告，不能用单次推理延迟代替整任务耗时。
- 每成功任务能量＝全部尝试的总能量÷成功数，包含失败尝试的成本；不是仅对成功样本取平均。

## 3. 闭环如何运行

1. Full生成未来50步动作，并读取尚未执行部分的夹爪、减速、转向提示。夹爪阈值±0.2，连续2个预测动作确认；减速依据平移命令幅度下降；转向依据相邻预测方向变化。它们是动作命令提示，不是物理接触识别。
2. 将最早关键事件与有效动作缓冲耗尽时间取早，确定本次结果应到达的时间。H＝50是预测上限，不是每次固定执行50步；RTC已承诺前缀和实际推理延迟仍限制最晚提交。
3. 按设备当前状态选择完整服务耗时P95。服务耗时从准备设备开始，到新动作可提交，低频恢复开销包含在内。
4. 最晚启动＝min(缓冲截止，关键事件截止)－状态相关P95－额外余量η。没有待刷新需求时执行Continue；可用空档达到现有约200 ms门槛时尝试降频，不固定等待时长。
5. 联合调度将恢复开销纳入启动预算；恢复时机器人继续执行已有动作。本次推理完成前保持高频，RTC随后按真实进度提交新动作。
6. 完成请求后更新服务耗时历史与事件覆盖状态，继续下一轮。P95在线更新，余量对照中η固定，不同时改变两个参数。

## 5. 额外余量校准：采用25 ms

初筛比较50、25、0 ms，三集合task1共9回合；全部成功、无断供。50/25/0 ms总能量分别286.84/286.20/299.70 J，刷新迟到分别2/2/8次。0 ms不采用。

随后进行50与25 ms两轮独立运行，每轮三个集合各task1、3、6，共18回合，合计36回合；每轮只加载一次模型，第二轮反转任务顺序。第二轮首次因环境像素预检查未通过而停止，未加载模型，之后仅补第二轮，不重跑第一轮。

25 ms两轮均略省电，合计减少约1.4%，任务总时间基本相同，成功结果一致，未观察到实际动作断供。第一轮Goal task1首次预测存在微小差异，第二轮全部配对一致；该记录保留，因此不把1.4%解释为精确、普遍的收益。基于当前工程证据，本阶段选择25 ms，后续正常实验持续监控迟到与断供。

ε固定0.05，即使用在线P95；本轮没有比较不同ε。两轮日志中高频直接刷新67个样本，P95/P99为560.8/579.2 ms，差18.3 ms；低频恢复后刷新105个样本，P95/P99为621.4/645.2 ms，差23.8 ms。采用最近秩经验分位数。这里是完整批次回顾统计，不等于每次调度当时可见的在线预算；样本不多，不能将P99当作硬实时上限，也不能将P95＋25 ms直接称为P99。

**迟到与断供分开解释。**迟到指未赶上预测的关键事件/缓冲截止时间；断供指真实动作队列已经耗尽。已有日志中，许多关键事件在新动作预测出来时已经太近，立即启动也来不及；这不是单靠调整η就能消除的问题。50/25 ms均无实际断供，不代表所有关键事件时限都已满足。

## 6. 正确性与故障恢复

- 主表9个任务的初始观测、state、噪声及首次动作经过严格配对检查；C组异常复测后全部一致。真实异步后续观测与时序允许随策略发生变化。
- 主比较回合的频率恢复、推理窗口高频以及板级功率完整覆盖检查通过；余量对照逐回合同样保留检查。
- 看门狗已进行真实模型故障注入：额外推理延迟、动作缓冲耗尽和推理无返回。前两种保留恢复后实际执行新动作的记录；卡住时普通用户工作进程按3秒请求期限及外层3秒清理退出，独立有界调频助手恢复频率。
- 原有900 MiB阶段检查与768 MiB外层内存保护保留。主批内存中断时模型显存没有持续增长，附近新增远程编辑器进程与外部内存竞争一致；不将其直接写成已定位的模型内存泄漏。

## 7. 验收与后续工作

M3最小闭环的实现和实验验证完成：Full/Continue、机制一、状态相关完整服务预算、最晚启动、低频等待/提前恢复、RTC、能量计量和故障恢复均已接通，并完成四组比较和余量对照。

本阶段收益：动态刷新大幅减少不必要推理；在相同动态刷新策略上，设备联合调度进一步降低板级能量。主要问题是部分预测关键事件发现过晚、少量渲染/首次预测差异，以及低频独立调度与联合调度的收益差距仍小。

后续顺序：先将选定η＝25 ms同步到正式配置并冻结版本；再进入M4，在已有闭环中验证Fast/Full选择及对应的状态服务/能量预算。Fast不提前计入M3收益。机制一进一步优化与更广任务、扰动验证后续开展，不因当前零断供声称所有条件下都可靠。
