# 执行进度补充信号小测：自动刷新暂不采用

新增的state信号能定位部分推盘、放置接触过程，但两轮开发小测未证明自动刷新有稳定净收益。自动触发代码已归档，主线保留原阶段去重和RTC承诺前缀修正，FlashRT未修改。

## 检测内容

只读取已完成动作的Z指令和机械臂state中的末端高度。前8个有效下压动作建立本回合的正常响应参考；最近3步仍明显要求下降、实际下降响应不足参考的20%，记录一次信号。恢复响应达到40%或离开下压指令段持续3次后才重新允许记录。

这表示下降进度不足，不代表已判断接触或抓取成功。信号落在已预测的夹爪闭合保护区间内时屏蔽整段，避免打断抓取。每次刷新仍采最新双图/state，原RTC、H50/N5/BF16、seed7/init0和三频调度保持。

第一版直接根据该信号申请新Full；第二版增加未来动作检查：只有当前计划接下来仍连续下压至少5步，才响应；计划已经准备停止时丢弃这次请求。5步沿用现有最小执行窗口，没有逐任务调整。

每对两组都计算监测信号，分别为“只记录”和“据此刷新”，因此不会把检测计算本身当作刷新收益。检测与5步查询的CPU耗时中位约0.016ms、p95约0.019ms，6000个保存数据样本；不含模型推理、成像或日志写入。

## 第一版结果

Goal5推盘：原组300步超时，新组173步成功。两组前50步物理和动作完全相同，前两份预测raw相同；在50步补采新观测后才开始出现动作差异。新组两次紧急刷新共等待约0.98秒。

但随后三个任务的补测发现正常放置会多次刷新。第一版四任务共8回合、2次模型加载，成功2/4→3/4，总模块输入能量589.39→637.48J，反而增加8.16%。其中部分补测在首次新信号生效前已有异步轨迹差异，不把全部差额单独归因为该规则。

## 如何理解波动

两轮属于不同模型加载，不能把跨批成功变化直接归因为新增的5步条件。Goal5两轮的初始双图、归一化state和噪声一致，但首预测raw最大绝对差约0.006523，执行动作从0步就有细微差异；之后观测和交接又继续分化。此差异未在本轮唯一定位来源。

两轮各自的配对初始输出一致，因此每轮内部对照仍成立。当前证据说明：新的物理反馈有机会纠偏，但“下降受阻”也可能是正常推压或放稳，不能自动等价为需要再算一次Full。
