# M3关键位置短暂等待

2026-10-31，用户授权实验。开关`--critical-wait`，仅支持M3，默认关闭，Fast不启用。基于当前机制一已经选中的action_event刷新，不更改阈值或增添关键事件。

原有异步照常运行。若新推理仍未提交，执行步抵达该次请求记录的critical_step，则在执行这一动作之前暂停仿真；轮询原有harvest及请求看门狗，直到该次结果提交。推理不取消、不重算。暂停期间不调用env.step、不消费队列、不增加执行步；RTC提交按真实执行位置截取新动作，延迟队列也记录真实执行步数。它不改变已启动推理时使用的前缀估计。

每次等待记录critical_wait trace事件和请求字段；episode输出critical_wait_count及critical_wait_seconds。等待计入整任务真实耗时与能量，控制周期估计扣除显式等待，避免将暂停解释成执行变慢。

这是仿真内的暂停实验；真实机械臂的保持控制需另行实现。事件触发之前就已执行过的关键动作无法补救，也不假定等待必然提高成功率。

先测原Object task0（规范任务索引3），和同任务历史M3对照；不先跑12回合。代码与CPU回归检查通过后仍需真实GPU闭环验证。
