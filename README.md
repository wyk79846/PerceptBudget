# PerceptBudget

在 Jetson Orin NX 上评估 π0.5 的动作刷新频率与任务质量、耗电之间的关系。已有最小异步评测程序和功率记录工具，CPU 测试与实际环境输入检查通过；CUDA 扩展编译、导入及模型短测已通过。旧轮45次同机仿真 q 初筛保留为历史结果；当前 M1.1 新轮按30个不同任务、每个任务覆盖5个 q 共150次正式运行重启。尚无真实20Hz闭环或低功耗节能结论。

## M1 协议

先做 **M1.1 q 评测**，再做 **M1.2 功率与耗电核验**。

固定目标配置：当前 `pi05_libero_pytorch` 权重、BF16、去噪步数 `N=10`、启用机械臂 state、预测长度 `H=20`。H=20 输出已短测验证，但不代表任务质量通过。测试 `q=5、8、10、12、15`，以 `q=5` 为基准；选取30个不同的 LIBERO 任务，Spatial、Object、Goal 各10个。全局 task ID 为0–9 Spatial、10–19 Object、20–29 Goal；开跑时核对 ID 对应的任务名称。每个任务在每个 q 下各运行一次，共 **150 次正式运行**。统一 seed=7、初态索引 0、控制频率和 `MAX_STEPS=220` 正式控制步；220步与旧轮一致，各任务使用同一上限。复杂新任务可能在220步内未完成，须记录实际失败或超时原因，不能仅凭失败自动归因于 q。单独的 q=5 冒烟检查不计入150次。

每个 q 下总体样本为30个任务，单个任务对应约3.33个百分点；每个 suite 有10个任务，suite 内单个任务对应10个百分点。结果必须按 Spatial、Object、Goal 分别报告各 q 的成功数/任务数及失败情况，并附总体汇总，不能只给总平均。该轮用于看趋势，不据此精确验证成功率差异或5–10个百分点的统计门槛。

独立短测已验证 BF16、处理后的 state 输入及 `H=20` 输出；正式运行继续记录实际配置和异常。`H=20` 输出不代表任务质量通过。不修改 FlashRT，也不复制旧动作凑长度。`H` 是单次预测动作数，`q` 是执行多少个动作后重新观测并推理。

### M1.1：q 评测

记录每次运行的 suite、task ID 与名称、q、成功/失败/超时、已执行步数、推理次数、异常现象和可用的动作缓冲信息。输出按 suite 分层的 q 对比表、总体汇总、主要失败原因和候选设置。每个 suite 仅10个任务，结果用于看趋势，不据此声称精确验证成功率差异或5–10个百分点的统计门槛。实际仿真慢于20Hz，不能把仿真结果描述成真实20Hz闭环表现。

### M1.2：功率与耗电

在 M1.1 后测量推理期间与无推理期间的功率，并整理各 q 的整次任务耗电。使用相同设备功耗模式，记录功率读数覆盖模块还是整板；功率积分与真实运行耗时使用同一任务窗口。没有可靠读数就标记未测，不推断节能收益。以实际能耗比较 `q=5` 与候选设置，同时报告成功次数和任务时间，避免把任务变慢误当成节能。

### 计时与运行模式

- 任务完成时间按 **正式控制步数 × 固定控制周期** 计算；控制周期从实际配置读取并在各组保持一致。
- 真实运行耗时单独用单调时钟计量，从正式任务开始到结束，包含推理、等待和调度开销。任务完成时间与真实运行耗时分别报告，不用单次推理时间替代。
- 每次运行标明 **异步执行** 或 **同步诊断**。异步执行可与控制重叠；同步诊断若暂停仿真，暂停时间只计入真实运行耗时，不计入仿真控制步时间，不能当作异步闭环结果。
- 成功、失败和超时分别记录；失败不伪造成功完成时间。只在共同成功的相同任务间比较完成时间，并同时报告成功次数。

## 当前代码与运行结果

- `perceptbudget/experiment.py`、`scripts/new_run.py`：读取配置并创建仓库外的独立 run 目录，保存配置快照等管理信息。
- `scripts/check_setup.py`：只读检查路径和配置；字段检查不代表后端已实际使用相应精度或输入。
- `scripts/run_flashrt.py`：在独立进程入口选择配置的 FlashRT 源码。
- `perceptbudget/control.py`：一个推理请求在途的动作队列，按控制步对齐，记录过期动作和断供。
- `perceptbudget/libero_input.py`、`model.py`：双图/state 预处理与原版前端适配，不修改 FlashRT。
- `perceptbudget/power.py`：只读 VDD_IN 采样与积分，标明数据覆盖度，缺读不冒称总耗电。
- `scripts/eval_q.py`：环境检查、单条 smoke 和本轮150次正式 q 测试；`guarded_run.py` 在低内存时停止自己启动的进程组。
- `config.json` 保存上述目标配置。配置值和检查脚本本身不代表实际验证；加载、H=20 和 state 延迟的依据为独立短测，旧轮初筛结果已保存，新轮结果待完成；尚未验证真实20Hz及低功耗配置。

## 边界

- 使用固定原版 FlashRT 加上述两个已授权补丁；其余源码不改，实验控制和后续策略放在本项目。
- 不把计划、配置或管理工具描述成已完成评测；节能结论必须有实际功率/能耗记录。
- 若 state 预处理规范未确认，不猜测归一化或自行补维；`state_enabled=true` 本身不能证明 state 已进入模型。
- 保持旧 LUTVLA、共享依赖和现有虚拟环境不变。未经明确安排，不并发运行 GPU 作业。
