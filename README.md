# PerceptBudget

**为灵玑 OS 构建更加省电、同时追求高准确率的 VLA 推理方案。**

PerceptBudget 面向机器人端侧的视觉—语言—动作模型推理，通过按需刷新感知、选择 Full/Fast 推理模式和调节设备频率，减少执行过程中的冗余计算。当前以 π0.5 和 NVIDIA Jetson Orin 为验证平台，用任务成功率衡量任务完成能力，同时记录整任务能量、完成时间与动作供给情况。

## 方案

| 模式 | 行为 | 用途 |
|---|---|---|
| Full | 双视角共 512 个视觉 token，输入完整的 32 维填充 state | 获取完整上下文并更新动作计划 |
| Fast | 外部视角 64＋腕部视角 256 个视觉 token，输入 8 维实际 state | 在选定刷新阶段减少感知计算 |
| Continue | 继续执行已生成动作，根据可用空闲窗口降低设备频率 | 减少重复推理和执行间隙的能量消耗 |

刷新时机结合尚未执行的动作、夹爪切换、减速、转向和新旧预测变化判断。推理与控制真实异步运行，RTC 使用完整 VJP 引导衔接新旧动作。关键刷新采用高频，普通刷新优先使用满足时限的中频，Continue 使用低频。

推理后端为 **FlashRT 感知上下文＋OpenPI 动作专家**，使用 source-step CUDA Graph、条件缓存、FlashAttention 和融合归一化。比较过程保持同一 checkpoint、H=50、N=5 与 BF16 配置。

### 已测节能与成功率

25 个随机种子，每个种子覆盖四个 LIBERO 集合各 10 个任务，固定 init=1，两组各 1,000 回合。

| 指标 | 动态调度候选 | 固定异步 q10 |
|---|---:|---:|
| 任务成功 | 852/1,000（85.2%） | 873/1,000（87.3%） |
| 总任务能量，含失败 | 135,857.82 J | 244,824.41 J |
| 平均刷新间隔 | 22.23 步 | 10.00 步 |

候选总能量降低 **44.51%**；双方共同成功的 767 个配对任务中，能量降低 **44.76%**。候选成功率低 **2.1 个百分点**，后续继续围绕抓取反馈和接触阶段提高任务完成能力。

这组 1,000 回合结果属于**关闭额外补刷新之前的候选版**。当前最终 v4 关闭关键动作前的额外时效补刷新、保留夹爪抬起反馈；在 87 个实际触发过该机制的回合中，开关两组均成功 25 次，关闭后总能量少 2.95%。最终 v4 尚未重跑完整 1,000 回合，两个范围分别记录。

### AGX 推理验证

AGX Orin 64GB，H=50、N=5、BF16，GPU 频率 1,300.5 MHz，固定同一组预处理后的图像与 state：

| 路径 | 预热后的耗时 |
|---|---:|
| FlashRT 原生推理，不带 RTC | 160.59–160.72 ms，2 次功能验证计时 |
| Full＋RTC，正式 source-step CUDA Graph 路径 | 中位数 **299.58 ms**，12 次范围 298.99–300.39 ms |

RTC 图的动作输出与 VJP 范数通过同输入参考校验。计时包括视觉上下文、动作求解及 CPU 动作输出，不含取图、外部图像/state 预处理、控制执行、模型加载和图准备。AGX 上完整闭环的成功率及整任务节能仍待测量。

## 配置与检查

先准备兼容的 CUDA/PyTorch、FlashRT、OpenPI 与模型权重，并将 [config.json](config.json) 中的本机路径指向实际安装位置。默认基线配置见 [baseline.py](perceptbudget/baseline.py)；动态调度入口为 [run_m4.py](scripts/run_m4.py)，冻结 v4 的行为说明见 [版本记录](docs/MECHANISM1_V4.md)。

在已配置的 Python 环境中检查设置、查看固定 q10 基线的启动计划：

```bash
python scripts/check_setup.py
python scripts/run_baseline.py --suite libero_spatial --task-id 0 --q 10 --dry-run
```

上述命令不加载模型。动态调度需要设备成本数据与对应运行参数，详见[进度记录](docs/PROGRESS.md)。

## 项目目录

- `perceptbudget/`：推理适配、动作刷新、RTC、设备调度、功率记录与反馈模块。
- `scripts/`：基线运行、动态调度、标定、诊断与结果分析。
- `tests/`：功能、数值、时序与记录一致性检查。
- `patches/`：FlashRT 低内存加载和分词器缓存补丁。
- `docs/`：版本、实验方法、设备操作和进度记录。

模型权重、训练图像和大体积运行输出保存在仓库之外。公开的阶段汇总见 [docs/metrics/](docs/metrics/)；当前视觉反馈实验见[实验入口](docs/experiments/visual_monitor/README.md)。
