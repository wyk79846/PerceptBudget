# PerceptBudget

本项目用于逐步研究感知计算预算与可靠动作执行之间的关系。当前阶段只搭建最小项目骨架，尚未运行实验，也不报告性能、能耗或节省收益。

## 当前边界

- M1 候选 `q=5/8/10`，先验证可靠执行长度，再讨论节能。每次完整刷新输出 `10×7`，只消费前 `q` 个动作、丢弃尾段；消费期间不推理，之后完整刷新。不复用旧 chunked 流程的每步 `advance`；协议尚未实现或实验。
- 初筛拟选平稳搬运、接触放置各一类任务，每类 5 个相同初始状态；按初始状态配对 `q` 并随机化运行顺序，共 30 条轨迹，仅作筛查且尚未执行。首个基线失败先排查，区分运行无效与策略失败；单次策略失败不改变 `N`，以保持同组比较，不继续大范围扫描。
- 分别记录成功/失败/超时/运行无效、仿真动作步数、完整刷新次数、推理墙钟、纯任务墙钟（不含模型加载、预热、建环境）和仿真时间，不混用口径。没有功率积分数据，不宣称能耗收益。大 `q` 若损害质量或增加纠正则弃用；`q=5` 若有可用执行余量仍可评估节能，不设 `q>5` 门槛。
- `N=1` 仅继承此前计算设置，不保证成功率；模型、`H=10`、`N=1`、`fp16` 待首个基线确认，确认后同组 `q` 实验冻结。
- 单次动作输出 `H=10` 不保证全部动作都能可靠执行。
- 同步仿真在暂停期间测得的墙钟时间，不等于真实机器人完成时间。
- 旧 LUTVLA 实验不能作为本项目的能耗证据。
- Fast、异步执行与调频均尚未实现；本项目当前不实现模型推理、评测或节能控制。
- 模型、`N` 与精度保持冻结；state 默认关闭。不切块、不训练、不复制大型文件。结果写到项目目录之外。
- 共享 FlashRT 并非干净上游：审查记录 HEAD `e4fe123` 且有 7 个 dirty 文件。正式实验须记录 commit 和补丁状态/指纹；本轮不复制或修改补丁。可直接使用 FlashRT 与 LIBERO，不必导入旧 LUTVLA。
